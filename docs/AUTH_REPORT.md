- 验收时间：2026-11-07
- 环境：Windows / Python 3.12.10 / Streamlit 1.50.0 / Microsoft Edge（Playwright 无头模式）

## 二、功能验收

| 需求 | 结果 | 说明 |
| --- | --- | --- |
| 未登录拦截 | 通过 | 未登录访问任意站内页面，只展示登录 / 注册界面，不渲染顶部导航与业务页面 |
| 必须先注册才能登录 | 通过 | 使用未注册账号 `HXZ0001` 登录，提示「账号或密码不正确」并引导先注册 |
| 用户名自选 | 通过 | 注册时可自由填写 2–16 位中文、字母、数字或下划线用户名，英文不区分大小写且不可重名 |
| 账号号按注册顺序编号 | 通过 | 第 1 位用户得到 `HXZ0001`，第 2 位得到 `HXZ0002`；编号来自 SQLite 自增主键，稳定且可追溯 |
| 密码功能 | 通过 | 密码 8–32 位且需同时包含字母和数字；注册需二次确认；支持浏览器密码显隐 |
| 密码安全存储 | 通过 | 数据库只保存 `pbkdf2_sha256$260000$…` 加盐哈希，人工检查确认无明文密码 |
| 注册必须设置密保问答 | 通过 | 未填写密保问题或密保答案时不能创建账号；问题 2–60 字，答案 2–50 字 |
| 密保答案安全存储 | 通过 | 答案统一空白字符并忽略英文大小写后进行 PBKDF2 加盐哈希，数据库无明文答案 |
| 找回密码 · 验证账号 | 通过 | 在「找回密码」中输入账号号或用户名，正确读取该账号注册的密保问题 |
| 找回密码 · 错误答案 | 通过 | 输入错误密保答案时拒绝重置，并提示「密保答案不正确」 |
| 找回密码 · 重置密码 | 通过 | 正确答案可设置新密码；重置成功后回到登录页并自动带入账号号 |
| 密码重置生效 | 通过 | 旧密码登录失败，新密码登录成功 |
| 老账号兼容 | 通过 | 旧数据库自动补充密保字段；未设置密保问题的历史账号会提示无法自助找回 |
| 账号号登录 | 通过 | 注册成功后将 `HXZ0001` 自动带入登录框，输入密码可正常进入首页 |
| 用户名登录 | 通过 | 使用 `河宝2026` 的小写形式登录成功，验证大小写不敏感 |
| 登录态展示 | 通过 | 首页欢迎语显示当前用户名；顶部用户区显示用户名与账号号 |
| 退出登录 | 通过 | 点击顶部退出按钮清除当前浏览器会话并回到登录页 |
| 移动端适配 | 通过 | 390px 下登录 / 注册 / 找回三栏保持并排，页面宽度 390 / 视口 390，无横向溢出 |
| 控制台 | 通过 | 完整注册 → 登录 → 找回密码 → 新密码登录流程 0 个 console error、0 个 page exception |

## 三、接口与数据

| 项目 | 说明 |
| --- | --- |
| 账号库 | `.data/accounts.db`（首次注册时自动创建） |
| 账号号 | `HXZ` + 至少 4 位注册顺序号，如 `HXZ0001` |
| 密码算法 | PBKDF2-HMAC-SHA256，260,000 次迭代，16 字节随机盐 |
| 密保问答 | 问题明文用于展示；答案经规范化后使用与密码相同的加盐哈希保存 |
| 会话 | 当前浏览器 Streamlit 会话；退出时清理；密码重置会删除该账号的 Cookie 会话记录，其他设备刷新后需重新登录 |
| 测试数据 | 自动化测试使用独立临时库，不写入正式 `.data/accounts.db` |

## 四、已知边界

1. 本地账号系统只用于黑客松演示，正式上线应接入河南大学统一身份认证。
2. 当前登录态保存在 Streamlit 会话中，浏览器整页刷新后需要重新登录。
3. 密保问答属于轻量级身份校验，安全性低于短信 / 邮箱验证码或 MFA，仅用于黑客松演示；正式上线建议接入统一身份认证并提供短信 / 邮箱找回。
4. 早期注册、尚未设置密保问答的账号无法通过该方式自助找回，需重新注册演示账号。暂无修改密保问答的入口。
5. 演示系统不采集真实姓名、学号等身份信息，请勿使用真实校园密码或真实密保信息。
