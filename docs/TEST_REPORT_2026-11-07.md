## 二、发现并已修复的问题

### 1. 问答输入条「发送」按钮飘到框外（严重视觉缺陷）

- 现象：桌面端提问输入框右侧的蓝色「发送」按钮脱离圆角输入条，浮在页面左侧并压住内容。
- 原因：CSS 用 `position:absolute; right:7px` 定位按钮，但 Streamlit 1.50 中提交按钮的父容器宽度会塌缩成 16px，`right` 因此相对这个窄容器计算（按钮 x=51，输入条 x=122）。
- 修复：改为 flex 行布局——输入框 `flex:1`，按钮固定 94px（移动端 74px），不再使用绝对定位。
- 验证：按钮 x=873，落在输入条 122–974 区间内；390px 移动端无横向溢出。

### 2. 个人中心「修改 / 删除」按钮文字竖排

- 现象：任务行右侧两个按钮宽度只有 37px，「修改」被拆成上下两行，行高 59px，观感很差。
- 原因：操作列占比 12%，再对半分成两列，每列约 32px，放不下 2 个汉字 + 内边距。
- 修复：操作列占比提高到 18%，按钮加 `white-space:nowrap`。修复后按钮 50×34，单行显示。

### 3. 个人中心「删除」首次点击无任何反馈

- 现象：点「删除」后按钮文字不变，页面无提示；由于状态已置为确认态，用户连点两下会直接删掉任务，二次确认形同虚设。
- 原因：按钮在本轮渲染完成后才把 `confirm` 状态写入 `session_state`，缺少一次重跑，界面不刷新。
- 修复：写入确认态后立即 `st.rerun()`，按钮文字马上变成「确认?」，再点一次才真正删除。
- 验证：8 条任务 → 点击删除 → 出现「确认?」→ 确认后剩 7 条，数据文件同步减少。

## 三、顺带补上的功能缺口

### 报名记录刷新即丢失

- 现象：报名成功后刷新页面 / 换标签页 / 重新登录，报名状态全部消失（只存在 `session_state`）；页面文案却写着「已同步到个人事务中心」，与实际不符。
- 修复：
  - 报名记录改为按账号持久化到 `.data/registrations_<账号>.json`，刷新、重登后保留；
  - 切换账号时从各自文件恢复，不会串号；
  - 活动卡片新增「取消报名」入口（此前文案承诺可取消，但全站没有取消入口）；
  - 同步修正「退改说明」「我的活动行程」等处文案。
- 验证：报名 → 新标签页仍显示已报名 → 取消报名 → 再开新会话确认已取消。

## 四、未修复的观察项（建议）

1. **移动端顶部导航需横向滑动**：5 个导航项总宽 428px，超出 390px 视口，容器是 `overflow-x:auto` 且隐藏滚动条，最后一个「我的河大」默认看不见，容易被误认为缺失。建议在移动端改为等分紧凑排布或加入渐隐提示。
2. **字号偏小**：多处说明文字为 8–9.5px（如气泡底部注释、元信息），在高分屏或投影场景可读性偏弱，建议正文不小于 11px。
3. **两套任务体系并存**：个人中心「待办」与活动页「活动任务」是两套独立数据，数量不会互相累加，新用户容易疑惑。建议在活动任务看板注明「仅统计活动相关任务」，或在中心页做入口联动。
4. **未知账号登录会创建空会话**：登录失败也会写入一条 sessions 记录（HXZ9999），量大会产生垃圾数据，建议校验通过后再落库。
5. **AI 调用无超时重试**：当前 `HXZ_API_TIMEOUT=45`，失败直接回退本地库，回退体验良好；若后续演示网络抖动频繁，可加一次轻量重试。
